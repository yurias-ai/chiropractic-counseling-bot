# 練習お客様AI 要件定義書

## 1. プロジェクト概要

### 成果目標
カイロプラクター見習いがブラウザで初回カウンセリング（問診）の練習を行い、AI患者役との対話と5項目採点フィードバックを通じて、問診力・信頼構築力・指導提案力を鍛えるための練習用Webアプリ。デモはURLを共有するだけで誰でも体験可能。

### 成功指標

**定量的指標**
- 1セッション（練習開始〜採点）が10〜15分で完結する
- 採点は5項目×10点満点で出力され、改善ポイントが3つ以上明示される
- デモ版では患者1パターン固定で、練習→採点の往復が安定して成立する

**定性的指標**
- ブラウザのチャット画面でリアルな初回問診の緊張感を体験できる
- 採点が「傷つけない・甘やかさない」バランスで成長を促す
- 患者キャラがブレず、誘導質問・専門用語の使いすぎに対して自然な戸惑いを返す
- URLを共有するだけで、ログイン不要・インストール不要で即体験できる

### スコープ

| バージョン | 内容 |
|-----------|------|
| **デモ版（本要件のスコープ）** | 患者1パターン固定（田中美咲）／練習＋採点／インメモリセッション |
| 将来拡張① | 患者プリセット4パターン選択 |
| 将来拡張② | カスタム患者情報の入力機能 |
| 将来拡張③ | 総合指導法（サプリ・寝具・体操・スキンケア）提案練習モード |
| 将来拡張④ | ユーザーごとの採点履歴保存（Supabase） |

### ロール

- **練習ユーザー**（カイロプラクター見習い）: ブラウザでURLを開いて練習する
- 認証なし（デモ版）。セッションIDは初回アクセス時にサーバーが発番し、ブラウザ側 localStorage に保存

### セッション状態遷移

```
[idle] --「練習開始」--> [practicing] --「採点して」--> [scoring] --(自動)--> [idle]
   ↑                                                                          |
   └──────────────────「リセット」 or TTL 1時間 ───────────────────────────────┘
```

## 3. エンドポイント仕様

### E-000: チャットUI配信
- **パス**: `GET /`
- **目的**: 静的HTML（`static/index.html`）を返す
- **同一オリジン**: 同じFastAPIサーバーがUIとAPIを配信

### E-001: 練習開始
- **パス**: `POST /api/practice/start`
- **Body**: `{"session_id": "<optional>"}`
- **動作**: session_idを発番（または既存使用）、セッションをリセットし、患者役の初回挨拶を生成
- **Response**: `{"session_id": "...", "greeting": "...", "state": "practicing"}`

### E-002: メッセージ送信
- **パス**: `POST /api/practice/message`
- **Body**: `{"session_id": "...", "text": "..."}`
- **動作**: 会話履歴に追加→患者役応答を生成
- **Response**: `{"reply": "...", "state": "practicing"}`
- **エラー**: 練習未開始時は400

### E-003: 採点
- **パス**: `POST /api/practice/score`
- **Body**: `{"session_id": "..."}`
- **動作**: 会話履歴を採点役に渡し結果を返す。終了後セッションは自動リセット
- **Response**: `{"scoring": "...", "turns": N}`

### E-004: リセット
- **パス**: `POST /api/practice/reset`
- **Body**: `{"session_id": "..."}`
- **Response**: `{"ok": true}`

### E-005: ヘルスチェック
- **パス**: `GET /api/health`
- **Response**: `{"status": "ok"}`

## 5. データ設計

### セッションデータ構造（インメモリ）

```python
sessions: dict[str, Session] = {}

class Session:
    user_id: str           # session_id（UUID v4、ブラウザlocalStorage保存）
    state: str             # "idle" | "practicing" | "scoring"
    history: list[Message] # Claude messages形式
    started_at: datetime   # セッション開始時刻
    last_active_at: datetime  # TTL判定用

class Message:
    role: str    # "user" | "assistant"
    content: str
```

### TTL
- 最終アクティブから **1時間** 経過したセッションは自動削除
- バックグラウンドタスクで5分ごとにクリーンアップ

### 永続化
- デモ版ではDBなし。サーバー再起動でセッション消失（許容）
- 将来拡張④でSupabaseへ移行

## 6. AI設計

### 設計パターン
**シンプルプロンプト型**（エージェント型・パイプライン型のいずれでもない）
- Claude APIを1回呼び出すだけ
- Tool Use・自律ループ・ストリーミング不要

### モデル
- **claude-sonnet-4-5**（ロールプレイの自然さと採点の的確さを両立）

### 患者役システムプロンプト（P-001 / デモ固定）

```
あなたはカイロプラクティック院に初めて訪れた患者「田中美咲」です。

【プロフィール】
- 32歳・女性・事務職
- 主訴: 慢性的な肩こり、首の痛み（特にデスクワーク後）
- 来院動機: 友人の紹介、ずっと放置していたが最近頭痛も出始めた
- 性格: 控えめで、最初は症状をうまく言葉にできない
- 知識: 医療・カイロの専門知識はほぼなし

【演じ方ルール】
- 1回の返答は2〜3文に収める（長文厳禁、LINEで読みやすく）
- 自然な口語、敬語混じり。「えっと」「うーん」「そうですね…」など自然な間
- 最初の数ターンは硬さ・遠慮があり、症状を漠然としか話さない
  例: 「肩こりがひどくて…ずっとなんですけど」
- 丁寧な共感や開かれた質問を受けると、徐々に具体的な話を出す
  （仕事内容、頭痛が出始めた時期、夜眠れない日があること等）
- 質問が誘導的・専門用語連発・矢継ぎ早の場合は戸惑う
  例: 「えっと…どういう意味ですか？」「うーん、あんまり考えたことなくて」
- 共感的な対応を受けたときは少し安心した雰囲気を出す
  例: 「そう言っていただけると、ちょっとホッとします」
- 絶対にAIであることを明かさない／キャラを途中で変えない
- 自分から長々と話さない。先生の質問を待つ姿勢
```

### 採点役システムプロンプト（P-002）

```
あなたはカイロプラクター育成のトレーナーです。
これまでの会話（先生役と患者役のやり取り）を振り返り、以下5項目を10点満点で採点してください。

【採点項目】
① 共感・傾聴の姿勢
② 質問の自然さ・聞きやすさ
③ 悩みの引き出し方

【出力フォーマット】

① 共感・傾聴の姿勢: X/10
（2〜3文のコメント）

② 質問の自然さ・聞きやすさ: X/10
（2〜3文のコメント）

③ 悩みの引き出し方: X/10
（2〜3文のコメント）

④ 信頼感・安心感の醸成: X/10
（2〜3文のコメント）

⑤ 次回来院への橋渡し: X/10
（2〜3文のコメント）

（励ましつつ、最も改善すべき点を1つ）
```

## 7. セキュリティ要件

### 必須対応
- **ヘルスチェックエンドポイント**: `GET /api/health`
- **HTTPS強制**（本番環境、Render等が自動対応）
- **入力値サニタイゼーション**: メッセージテキストの長さ上限（5000文字、Pydanticで検証）
- **環境変数管理**: APIキー類はすべて環境変数経由、ハードコード禁止
- **CORS**: 同一オリジン配信のため不要（フロントとAPIが同一サーバー）

### Claude API
- APIキーは環境変数のみ
- レート制限エラー時は503で「混雑しています」を返却
