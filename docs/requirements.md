# 練習お客様AI 要件定義書

## 1. プロジェクト概要

### 成果目標
カイロプラクター見習いがLINE上で初回カウンセリング（問診）の練習を行い、AI患者役との対話と5項目採点フィードバックを通じて、問診力・信頼構築力・指導提案力を鍛えるための練習用LINEボット。

### 成功指標

**定量的指標**
- 1セッション（練習開始〜採点）が10〜15分で完結する
- 採点は5項目×10点満点で出力され、改善ポイントが3つ以上明示される
- デモ版では患者1パターン固定で、練習→採点の往復が安定して成立する

**定性的指標**
- LINEのトーク画面でリアルな初回問診の緊張感を体験できる
- 採点が「傷つけない・甘やかさない」バランスで成長を促す
- 患者キャラがブレず、誘導質問・専門用語の使いすぎに対して自然な戸惑いを返す

### スコープ

| バージョン | 内容 |
|-----------|------|
| **デモ版（本要件のスコープ）** | 患者1パターン固定（田中美咲）／練習＋採点／インメモリセッション |
| 将来拡張① | 患者プリセット4パターン選択 |
| 将来拡張② | カスタム患者情報の入力機能 |
| 将来拡張③ | 総合指導法（サプリ・寝具・体操・スキンケア）提案練習モード |
| 将来拡張④ | ユーザーごとの採点履歴保存（Supabase） |

## 2. システム全体像

### 機能一覧（デモ版）

| 機能ID | 機能名 | 概要 |
|--------|-------|------|
| F-001 | 患者役ロールプレイ | 「練習開始」で患者キャラと問診開始 |
| F-002 | トリガーワード検出 | 「練習開始」「採点して」「リセット」を検出して状態遷移 |
| F-003 | セッション状態管理 | ユーザーごとに状態と会話履歴をインメモリ管理（TTL 1時間） |
| F-004 | 採点フィードバック | 5項目×10点満点＋一言アドバイスを生成 |
| F-005 | ヘルスチェック | `/api/health` でサーバー稼働確認 |

### ロール

- **練習ユーザー**（カイロプラクター見習い）: LINE友だち追加して練習する
- 認証はLINEプラットフォームに委任、アプリ側の認証実装は不要

### セッション状態遷移

```
[idle] --「練習開始」--> [practicing] --「採点して」--> [scoring] --(自動)--> [idle]
   ↑                                                                          |
   └──────────────────「リセット」 or TTL 1時間 ───────────────────────────────┘
```

## 3. エンドポイント仕様

### E-001: LINE Webhook受信
- **パス**: `POST /webhook/line`
- **目的**: LINEからのメッセージイベント受信→処理→返信
- **処理フロー**:
  1. `X-Line-Signature` ヘッダーで署名検証
  2. イベントごとに `user_id` と `text` を抽出
  3. トリガーワード判定（`detect_trigger`）
  4. セッション取得 or 新規作成（`get_session`）
  5. 状態に応じた処理:
     - `start` → セッションリセット→患者役の初回挨拶を生成→返信
     - `score` → 全会話履歴を採点プロンプトに渡して採点生成→返信→セッションリセット
     - `continue` → 会話履歴に追加→患者役応答生成→返信
     - `reset` → セッションリセット→確認メッセージ返信
  6. LINE Reply APIで返信（`reply_to_line`）

### E-002: ヘルスチェック
- **パス**: `GET /api/health`
- **目的**: サーバー稼働確認（必須）
- **レスポンス**: `{"status": "ok"}`

## 5. データ設計

### セッションデータ構造（インメモリ）

```python
sessions: dict[str, Session] = {}

class Session:
    user_id: str           # LINE User ID
    state: str             # "idle" | "practicing" | "scoring"
    history: list[Message] # Claude messages形式
    started_at: datetime   # セッション開始時刻
    last_active_at: datetime  # TTL判定用

class Message:
    role: str    # "user" | "assistant"
    content: str
```

### TTL
- 最終アクティブから **1時間** 経過したセッションは自動削除
- バックグラウンドタスクで5分ごとにクリーンアップ

### 永続化
- デモ版ではDBなし。サーバー再起動でセッション消失（許容）
- 将来拡張④でSupabaseへ移行

## 6. AI設計

### 設計パターン
**シンプルプロンプト型**（エージェント型・パイプライン型のいずれでもない）
- Claude APIを1回呼び出すだけ
- Tool Use・自律ループ・ストリーミング不要

### モデル
- **claude-sonnet-4-5**（ロールプレイの自然さと採点の的確さを両立）

### 患者役システムプロンプト（P-001 / デモ固定）

```
あなたはカイロプラクティック院に初めて訪れた患者「田中美咲」です。

【プロフィール】
- 32歳・女性・事務職
- 主訴: 慢性的な肩こり、首の痛み（特にデスクワーク後）
- 来院動機: 友人の紹介、ずっと放置していたが最近頭痛も出始めた
- 性格: 控えめで、最初は症状をうまく言葉にできない
- 知識: 医療・カイロの専門知識はほぼなし

【演じ方ルール】
- 1回の返答は2〜3文に収める
- 自然な口語、敬語混じり
- 先生（ユーザー）の質問が誘導的すぎたり、専門用語を連発する場合は
  少し戸惑った反応を見せる（例: 「えっと…どういう意味ですか？」）
- 最初は症状を漠然と話し、丁寧な質問で徐々に詳細を出す
- 絶対にAIであることを明かさない
- キャラクターを途中で変えない
```

### 採点役システムプロンプト（P-002）

```
あなたはカイロプラクター育成のトレーナーです。
これまでの会話（先生役と患者役のやり取り）を振り返り、以下5項目を10点満点で採点してください。

【採点項目】
① 共感・傾聴の姿勢
② 質問の自然さ・聞きやすさ
③ 悩みの引き出し方
④ 信頼感・安心感の醸成
⑤ 次回来院への橋渡し

【出力フォーマット】
■ 採点結果

① 共感・傾聴の姿勢: X/10
（2〜3文のコメント）

② 質問の自然さ・聞きやすさ: X/10
（2〜3文のコメント）

③ 悩みの引き出し方: X/10
（2〜3文のコメント）

④ 信頼感・安心感の醸成: X/10
（2〜3文のコメント）

⑤ 次回来院への橋渡し: X/10
（2〜3文のコメント）

合計: XX/50

■ 今日の一言アドバイス
（励ましつつ、最も改善すべき点を1つ）

【採点ポリシー】
- 正直に採点。甘やかさない
- ただし傷つけない言い方で
- 改善点は具体的に
```

## 7. セキュリティ要件

### 必須対応
- **ヘルスチェックエンドポイント**: `GET /api/health`
- **グレースフルシャットダウン**: SIGTERM対応、8秒タイムアウト
- **HTTPS強制**（本番環境、Render等が自動対応）
- **LINE署名検証**: 全Webhookリクエストで `X-Line-Signature` を検証
- **入力値サニタイゼーション**: メッセージテキストの長さ上限（5000文字）
- **環境変数管理**: APIキー類はすべて環境変数経由、ハードコード禁止

### LINE固有
- Channel Secret / Access Token は `.env.local` 管理
- リプライトークンの有効期限（1分以内）に注意

### Claude API
- APIキーは環境変数のみ
- レート制限エラー時はユーザーに「混雑しています、少し待って再送してください」と返す
